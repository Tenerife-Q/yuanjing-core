## 一、 系统整体架构与交互流程

本项目（原镜 Yuanjing）旨在解决 **AIGC 虚假图像与图文错位谣言** 无法有效鉴真与追溯的痛点，采用“前端多模态模型推理 + 后端区块链不可篡改存证”架构：

```
[ 用户 / 测试图片 ]
       │
       ▼
[ ViRTA (Python / PyTorch) ]
 ├── VPRM : 图像视觉降质恢复 (NAFNet 架构)
 ├── ATM  : 自适应 Token 聚合 (保留 Key Patches 与 Global Anchors)
 └── FGAFM: 细粒度跨模态匹配 & 门控融合分类
       │ (输出 predicted_label: 0/1, confidence: 0.0~1.0)
       ▼
[ blockchain_bridge.py (SDK) ]
 ├── Label 转 Verdict 映射 (0 -> True 真, 1 -> False 假)
 ├── confidence 范围归一化 [0.0, 1.0] 兜底
 └── 转换为 JSON Payload 并发往 Rust 后端
       │ (HTTP POST http://localhost:3000/prove)
       ▼
[ yuanjing-core (Rust Backend) ]
 ├── fingerprint.rs : 提取 pHash (感知抗压缩) 与 SHA-256 (纯粹物理校验)
 ├── signer.rs      : BCS 规范化序列化 + Ed25519 签名确权
 ├── mmr_store.rs   : 校验 prompt_pool_hash 白名单 -> 写入 sled 数据库 + MMR 累加树
 └── api.rs         : 返回 root_hash, leaf_pos, signature 回执
```

## 二、 两个仓库的代码实现要点

### 1. `yuanjing-core` (Rust 区块链后端)

* **技术栈**: `axum`, `tokio`, `sled`, `ckb-merkle-mountain-range`, `ed25519-dalek`, `blake3`, `bcs`, `image`, `img_hash`.
* **核心模块划分**:
  * `src/evidence.rs`: 存证数据结构 `Evidence`，包含 `image_phash`, `image_sha256`, `verdict`, `confidence`, `activated_prompts`, `prompt_pool_hash`, `external_knowledge_hash`, `timestamp`。
  * `src/fingerprint.rs`: 双指纹计算逻辑。
    * `SHA-256`: 对文件二进制直接哈希，防止字节篡改。
    * `pHash`: 使用 `Gradient` 梯度算法计算 8x8 视觉哈希并转 Base64，抗社交媒体压缩。
  * `src/signer.rs`: Ed25519 密钥加载/生成与签名。先用 `bcs::to_bytes()` 做确定性序列化，再进行数字签名。
  * `src/mmr_store.rs`: 基于 Sled 嵌入式 KV 数据库的 Merkle Mountain Range (MMR) 存储，支持模型白名单 (`models_allowlist`) 校验与 $O(\log N)$ Merkle Proof 证据开具。
  * `src/api.rs`: HTTP 接口路由。
    * `POST /prove`: 接收存证请求，计算指纹、生成签名并追加写入 MMR。
    * `GET /audit/{pos}`: 获取指定位置节点的 Merkle Proof。
    * `POST /model/register`: 注册合法模型 Hash 到白名单。

### 2. `ViRTA` (Python AI 多模态模型)

* **技术栈**: PyTorch 2.8, torchvision, transformers, CLIP (OpenAI & Chinese-CLIP).
* **核心模块划分**:
  * `ViRTA.py`: 主模型定义。
  * `alignment.py`: 包含 `ATM` (自适应 Token 模块) 与 `FGAFM` (细粒度自适应融合模块)。
  * `clip_encoders.py`: 封装中文/英文 CLIP 编码器。
  * `train_virta.py`: 模型训练脚本（支持 Weibo 与 GossipCop 数据集及十折交叉验证）。
  * `blockchain_bridge.py`: 与 Rust 后端通信的桥接 SDK。

## 三、 代码排查发现的问题与修复记录 (Audit & Fixes)

1. **`yuanjing-core` 缺乏单元测试问题**：
   * *原状*：`cargo test` 提示 0 passed / 0 failed。
   * *修复*：在 `signer.rs`、`mmr_store.rs`、`fingerprint.rs` 中补充了 4 个单元测试，已全面验证签名防篡改、MMR 累加树开具证明、白名单拦截与指纹生成。
2. **`verify_demo.py` 字段报错问题**：
   * *原状*：请求体遗漏 `prompt_pool_hash` 导致反序列化失败。
   * *修复*：补充了 `prompt_pool_hash` 字段，确保接口正常。
3. **跨语言闭联调补全**：
   * *原状*：`ViRTA` 与 `yuanjing-core` 缺乏可运行的联调代码。
   * *修复*：编写了 `blockchain_bridge.py` 与 `test_virta_blockchain_integration.py`，打通了全流程。
